Bộ desktop X11 tối giản: tiling + monocle, bar có sysmon và tasklist kiểu Awesome, compositor dani-comp, launcher dani-run thay rofi, và chat AI dani-ai trong terminal. Không Electron, không framework — chỉ C với Xlib và một file Python stdlib.

Tính năng

Tiling + monocle, 5 workspace mặc định (1–10), gaps, EWMH, đa màn hình, rules, scratchpad, autostart, system tray. Source trong src/ — C thuần với Xlib, chia thành các module nhỏ (layout, bar, ewmh, mouse, keys, tray, sysmon…).

Tiling & monocle

Master + stack, mfact/nmaster chỉnh live, gaps trong/ngoài, toggle tức thì bằng Super+t/m.

Đa màn hình

Chia tile riêng từng monitor qua Xinerama (fallback: toàn màn hình); cửa sổ mới mở ở monitor có con trỏ; RandR hotplug re-tile không cần restart.

EWMH đầy đủ

_NET_SUPPORTED/CLIENT_LIST/ACTIVE_WINDOW, fullscreen, struts (_NET_WM_STRUT_PARTIAL, _NET_WORKAREA) cho bar ngoài như Polybar/Tint2/Lemonbar, pager, wmctrl, dock, window-type float.

Bar tích hợp

CPU/MEM/BAT/VOL + đồng hồ, tasklist Awesome-style, tray XEmbed, UTF-8 qua Xft (tiếng Việt), icon Nerd Font có fallback ASCII.

Drag & drop kiểu bspwm

Super+kéo cửa sổ lên tile khác để hoán đổi (tile đích sáng viền dày); thả ra ngoài thành float, thả sang monitor khác thì re-tile.

Compositor dani-comp

Shadow mềm 7 lớp kiểu picom, fade-in 160ms, dim cửa sổ không focus, tôn trọng _NET_WM_WINDOW_OPACITY.

Launcher dani-run

Thay rofi: danh sách drun fuzzy, icon thật từ icon theme, grid favorite, power menu, calculator.

AI chat dani-ai

BYOK, OpenAI-compatible, tool use, provider profile, session/undo, paste ảnh — mở bằng Super+Shift+a.

Restart giữ client

Super+Ctrl+r exec binary mới đè lên process cũ — cửa sổ, workspace, fullscreen và focus còn nguyên.

Test headless

Hàng chục suite trên Xvfb + xdotool (geometry, strut, randr, tray, restart, click-delivery, focus-model…), chạy được từ Wayland.

Build & chạy

Cần header X11 + Xinerama + Xrandr + Xft; dani-comp thêm Composite/Damage/Render/Fixes (thường có sẵn cùng libX11-devel).

make                 # build ./daniwm (warning nghiêm ngặt, fortified)
make check           # build + chạy toàn bộ suite headless (cần Xvfb, xterm, xdotool)
sudo make install    # -> /usr/local/bin + xsessions entry + share/daniwm/*.example
                     #    + user config vào ~/.config/daniwm/ (không ghi đè)
make install-user    # chỉ copy config + autostart.sh + run.config (không ghi đè)

Gói phụ thuộc trên Fedora

sudo dnf install libX11-devel libXinerama-devel libXrandr-devel libXft-devel
# compositor
sudo dnf install libXcomposite-devel libXdamage-devel libXrender-devel libXfixes-devel

Chạy thử

Xephyr :1 & DISPLAY=:1 ./daniwm      # cửa sổ lồng để thử
# session thật: exec ~/daniwm/daniwm   (trong ~/.xinitrc)
Install an toàn: make install không bao giờ ghi đè ~/.config/daniwm/config, autostart.sh, run.config — file đã có được giữ nguyên. Khi đóng gói với DESTDIR, bước cấu hình user được bỏ qua và chỉ cài config.example + run.config.example + autostart.sh.example vào $(PREFIX)/share/daniwm/ để copy tay.

Chuột & focus

  • Hover focus kiểu sloppy: rê chuột qua cửa sổ là active nhưng không restack — cửa sổ float nhỏ nằm trong cửa sổ lớn vẫn bấm được.
  • Click thường không bị WM "ăn": WM quan sát qua XI2 raw events, nên click vào cửa sổ float đưa nó lên trước (click-to-raise) mà app vẫn nhận đủ press/release.
  • Super+click dùng cho move/resize drag; Super+j/k đổi focus kèm raise.
  • Bar: click số 1..N để chuyển ws (active = pill + chữ sáng, occupied = sáng + dot, urgent = rose); task button trái = focus, giữa = đóng; scroll trên ws = ws trước/sau (wrap), scroll chỗ khác = volume, click trái module volume = mute.
  • Backend volume tự chọn: amixer → wpctl → pactl; phím XF86Audio* trên laptop dùng được ngay.

Config

File ~/.config/daniwm/config (hoặc $XDG_CONFIG_HOME/daniwm/config), dạng key = value, # là comment.

Không có file → dùng mặc định. Dòng sai → in stderr rồi bỏ qua, WM vẫn chạy. Super+Shift+r reload và áp dụng live các giá trị như scale, tên workspace, tray, màu bar — không cần khởi động lại.

Ví dụ

workspaces = 3
ws_names = Web Code Chat
rule = Gimp:*:float:*
bind = mod+3:ws3
bind+ = mod+a:spawn_menu

Rules và binds

  • rule = class:title:float:ws[:layout] — * = bất kỳ, float = float|tile, ws 1-based ≤ workspaces, layout tuỳ chọn tile|monocle.
  • bind = mod+key:action — modifier mod/super/alt/ctrl/shift + X keysym.
  • Dòng rule/bind đầu tiên thay bộ mặc định; bind+ để thêm mà không mất phím cũ. Bind wsN/mvN thiếu được tự điền theo workspaces (trừ khi combo đã bị bind khác chiếm), nên tăng workspaces không làm ws nào mất đường vào.
  • Reload giữ mfact/nmaster live của từng workspace (giá trị trong config chỉ là mặc định lúc khởi động); giảm workspaces thì workspace dư gộp vào cái cuối.

Actions cho bind

focus_next/prev, zoom, ws_toggle, kill, tile/monocle/toggle, spawn_term/menu, mfact_dec/inc (bước 0.025), nmaster_dec/inc, gap/gap_dec/gap_inc, bar, move_left/right/up/down (tiled: đổi vị trí trong layout; floating: 20px), resize_w_dec/inc, resize_h_dec/inc, vol_up/vol_down/vol_mute (amixer set Master 5%+/5%-/toggle), wsN (view), mvN (move + follow), float, fullscreen, scratch, ws_rename (prompt đổi tên qua rename_cmd; Esc giữ tên cũ, Enter trống xoá về số; WM không freeze lúc gõ), reload_config, restart, compositor (toggle dani-comp), quit.

Rule mặc định & scratchpad

  • Mặc định scratchpad, Gimp và mpv float. Window-type dialog/utility/toolbar/splash/menu/dropdown/popup/tooltip/notification/combo/dnd và modal luôn float.
  • Scratchpad: Super+s toggle xterm -name scratchpad (float 2/3 màn hình, giữa, lần đầu thì spawn). Lệnh scratch = tự đặt phải tạo cửa sổ có scratchpad trong class/name (vd alacritty --class scratchpad), nếu không toggle sẽ spawn liên tục thay vì toggle.
  • Autostart: chạy ~/.config/daniwm/autostart.sh nếu file có quyền thực thi.

Restart giữ client

Super+Ctrl+r (action restart) exec binary mới đè lên process đang chạy — client sống hết, giữ workspace (_NET_WM_DESKTOP), fullscreen, desktop hiện tại, focus và scratchpad đã park; trạng thái float và layout/mfact/nmaster từng ws trở về mặc định. Watcher bên ngoài phát hiện re-exec qua stamp _DANIWM_HEARTBEAT trên root (PID giữ nguyên qua exec, và X server có thể tái dùng window ID).

Bar

Bar do WM tự vẽ bằng Xft — UTF-8 với fallback từng glyph, nên tiếng Việt và symbol đều hiển thị đúng.

Bên phải: sysmon

  • Icon Nerd Font + giá trị: CPU MEM BAT VOL DD/MM HH:MM, phân cách · tuỳ chỉnh.
  • Không có Nerd Font → fallback chữ C/M/B/V; ico_clk fallback về không icon (giữ look clock cũ).
  • Pin yếu / MUTE / CPU ≥ 80% / MEM ≥ 80% hiển thị màu urgent; pin và volume ẩn nếu không có nguồn, volume cache 2 giây.
  • Icon pin/volume đổi theo mức, trạng thái sạc, mute. Layout hiện icon tile/monocle + số cửa sổ, không ngoặc.
  • Tuỳ biến: bar_modules (thứ tự + ẩn/hiện), ico_cpu/ico_mem/ico_bat/ico_vol/ico_mute/ico_clk (glyph riêng, để trống = không icon), clock_fmt (strftime), bar_sep_str, bar_gap (0–8), bar_pad_l/bar_pad_r.

Tasklist & workspace

  • bar_show_tasks (mặc định 1): task button mỗi cửa sổ trên ws hiện tại, overflow gộp thành chip +N; task button thay cho title đơn lẻ.
  • bar_task_w (0 = chia đều, hoặc px cố định), bar_task_pad (mặc định 6), bar_ws_task_gap (khoảng chết + divider, tránh click nhầm).
  • bar_ws_style / bar_task_style: pill (mặc định), underline, block, none; bar_task_style = follow theo bar_ws_style.
  • bar_task_active, bar_task_active_text, bar_task_text (alias bar_task_normal) — màu nền/chữ task, urgent vẫn dùng bar_urgent.
  • ws_names nhận vị trí (Web Code Chat) hoặc có index (1:Web 2:Code), quote giữ space; ws_name_N override từng ws; cell tự giãn theo tên.
  • bar_show_title / bar_show_layout để tắt title hoặc layout icon; title dài bị cắt bằng ….

Màu & tray

  • Nền tảng: bar_bg/bar_fg/bar_acc/bar_dim; override từng phần: bar_ws_active, bar_ws_active_text, bar_ws_occ, bar_ws_empty, bar_urgent, bar_sep, bar_mode, bar_title, bar_sys — phần không đặt thì fallback về màu nền tảng.
  • Tray XEmbed (_NET_SYSTEM_TRAY_Sn) ở mép phải: nm-applet --indicator, volumeicon, cbatticon tự dock; có divider tách tray và clock; selection mất owner được tự lấy lại.
  • tray = 0 để tắt (reload áp dụng ngay), tray_gap (0–32, mặc định 6) chỉnh khoảng cách icon; icon tray cao bar_h-10, tối đa 22px.
  • Click vùng tray không lọt sang workspace view.
Giới hạn: chỉ XEmbed cổ điển — app dùng StatusNotifier/AppIndicator cần cầu snixembed.

Compositor — dani-comp

Thay thế picom nếu bạn thích: shadow mềm 7 lớp kiểu picom, fade-in 160ms, dim cửa sổ không focus.

dani-comp                          # chạy với mặc định
dani-comp --no-shadow --no-fade    # tắt hiệu ứng
dani-comp --dim 0.8                # độ sáng cửa sổ không focus (0.5..1)
./test/test-comp.sh                # suite test riêng
  • Tôn trọng _NET_WM_WINDOW_OPACITY (dùng được với transset).
  • Quảng bá _NET_WM_CM_Sn; nếu picom đã chạy thì tự nhường.
  • Tự spawn khi compositor = 1 trong config; action compositor (ví dụ bind = mod+c:compositor) bật/tắt live.
Giới hạn: double-buffered nên không nháy, nhưng background lấy snapshot từ _XROOTPMAP_ID (root màu đặc chỉ clear 1 lần khi đổi bg), cửa sổ shaped bị clip trên back buffer, không có vsync thật.

Launcher — dani-run

Thay rofi: danh sách app fuzzy, icon thật từ icon theme, grid favorite, power menu và calculator.

dani-run              # danh sách drun fuzzy (dọc)
dani-run --fav        # grid icon app yêu thích, gõ để lọc
dani-run --power      # power menu (dùng lại UI fav)
dani-run --calc       # calculator: + - * / % ^, ngoặc, sqrt/sin/cos/tan/exp/abs/ln/log, pi/e
  • Quét /usr/share/applications + ~/.local/share/applications; app Terminal=true được bọc trong ${TERMINAL:-alacritty} -e.
  • Sắp xếp fuzzy + history ở ~/.cache/dani-run/history; icon PNG thật qua cairo nếu có, không thì fallback glyph Nerd/chữ cái đầu (drun_icons = 0 để tắt icon).
  • Cấu hình ~/.config/daniwm/run.config (symlink về repo): app = icon;name;cmd, power = ..., cols, lines, font; dòng app/power đầu tiên xoá danh sách mặc định.
  • Phím: mũi tên / Ctrl+h/j/k/l di chuyển, Enter chạy (input không khớp app sẽ chạy như lệnh), Esc thoát, scroll chuột = trước/sau. Trong --calc, Enter copy kết quả vào clipboard và in ra stdout.
Config của repo này dùng danh sách bind = đầy đủ (ví dụ mod+d = menu, mod+Shift+q = kill) và bind+ để thêm (mod+a = fav, mod+Shift+p = power) mà không mất phím cũ.

AI chat — dani-ai

BYOK, OpenAI-compatible, Python stdlib một file — không pip, không venv. Mở trong daniwm bằng Super+Shift+a.

dani-ai "cau hoi"                 # hỏi nhanh (stream mặc định)
dani-ai chat                      # REPL tương tác
dani-ai chat --continue [ten]     # mở lại chat cũ (ID riêng; last = checkpoint mới nhất)
dani-ai models                    # liệt kê model từ API
dani-ai history                   # liệt kê chat đã lưu
dani-ai history export TEN json ~/chat-backup.json   # xuất (json|md), local, không cần key
dani-ai history delete TEN CONFIRM                   # xoá đúng snapshot TEN
dani-ai tools                     # liệt kê tool builtin + custom
cat README.md | dani-ai --no-tools "Tom tat"         # chế độ pipe

Key, endpoint, model

Key: --api-key → DANI_AI_API_KEY → OPENAI_API_KEY → DEEPSEEK_API_KEY → ~/.config/daniwm/ai.key (3 dòng: key, base, model). System prompt: --system → --system-file → DANI_AI_SYSTEM_FILE → ~/.config/daniwm/ai.system.

# Chạy trong repo daniwm
cp ai.system.example ~/.config/daniwm/ai.system
dani-ai --system "Trả lời ngắn gọn bằng tiếng Việt." "Giải thích X11"
dani-ai --show-config             # xem cấu hình đã resolve
Đường dẫn: DANI_AI_KEY_FILE đổi vị trí file key; DANI_AI_API_BASE/DANI_AI_MODEL đổi endpoint/model. Mọi đường dẫn cấu hình mặc định dùng $XDG_CONFIG_HOME/daniwm nếu biến này được đặt, thay cho ~/.config/daniwm.

Provider profiles (opt-in)

--profile NAME + ~/.config/daniwm/ai.profiles.json (nên chmod 600) ghim base URL, model và tên biến môi trường chứa key; khai báo capabilities thủ công (tools, vision, stream, token_parameter) — không tự probe.

{
  "version": 1,
  "profiles": {
    "openai-mini": {
      "base": "https://api.openai.com/v1",
      "model": "gpt-4o-mini",
      "key_env": "OPENAI_API_KEY",
      "capabilities": {
        "tools": true, "vision": true, "stream": true,
        "token_parameter": "max_completion_tokens"
      }
    }
  }
}
  • Không dùng --profile thì key/base/model resolve như cũ; profile không fallback sang ai.key hay biến env khác.
  • Không lưu key trong JSON. --api-base/--api-key bị từ chối khi dùng profile; --model chỉ nhận nếu trùng model profile; /model bị khoá.
  • tools:false tắt runner, stream:false chọn nonstream, vision:false từ chối gửi ảnh kể cả khi resume; token_parameter = max_tokens | max_completion_tokens | null.
  • API request bị ràng buộc trong base profile; redirect khác origin vẫn bị chặn. File profile là cấu hình tin cậy — người sửa file có thể đổi nơi nhận key.

Paste ảnh

Ctrl+V đọc clipboard trực tiếp: ảnh PNG/JPEG/WebP/GIF hiện [Ảnh 1] (nhiều ảnh được, mỗi ảnh ≤10 MiB), text chèn tại con trỏ. Cần xclip (X11) hoặc wl-paste (Wayland), GNU readline có bracketed paste, và model/provider hỗ trợ vision + image_url. Ctrl+Shift+V vẫn là paste text của terminal.

Markdown & stream: render màu khi chạy trong TTY, giữ text thô khi pipe (--no-color/NO_COLOR để tắt). Stream phải kết thúc bằng [DONE] — JSON lỗi, error event hoặc stream cụt được báo lỗi và không lưu thành câu trả lời hoàn chỉnh.

Tool use

Bật mặc định; mặc định --permissions ask — hỏi trước khi ghi file, fetch URL, chạy shell/custom tool. Thao tác đọc file local không hỏi.

ToolChức năng và giới hạn
list_filesLiệt kê thư mục, không đệ quy, tối đa 200 mục.
read_fileĐọc UTF-8 tối đa 2 MiB; phân trang bằng offset/limit (limit ≤ 64.000), báo truncated và next_offset.
find_filesTìm đệ quy theo glob tên file; bỏ qua node_modules, vendor, build, dist, __pycache__, venv, coverage, *.o, *.pyc và glob trong .aiignore.
search_filesTìm chuỗi nguyên văn đệ quy, trả path:line:text; tối đa 2.000 entry/trang, 100 kết quả, có next_cursor; bỏ file >64 KiB hoặc binary.
search_textTìm chuỗi nguyên văn trong một file, tối đa 100 dòng khớp.
make_directoryTạo thư mục + cha còn thiếu, mode 700, từ chối symlink và path ngoài root.
write_fileChỉ tạo file mới, không ghi đè; thư mục cha phải có sẵn.
edit_fileThay một đoạn khớp chính xác một lần; lệch hoặc khớp nhiều lần → từ chối.
fetch_urlĐọc link công khai http(s), trả text + title (20 giây, 2 MiB, 16.000 ký tự); chặn scheme khác, URL có credential, host private/loopback/link-local (SSRF guard cho cả redirect) và file binary. Nội dung web là dữ liệu không đáng tin.
git_statusBranch + thay đổi của repo chứa tool root; không ghi index, không commit, bỏ submodule.
run_commandTắt mặc định; bật bằng --allow-shell hoặc /shell on. Chạy /bin/sh -c bằng quyền user, timeout 30 giây, output tối đa 64 KiB — không sandbox.

Quyền & chặn

  • --permissions ask (mặc định) hỏi xác nhận, hiện diff trước khi ghi file; read-only chỉ cho đọc file/search/git status (chặn cả fetch URL, shell, custom tool); workspace-write ghi trong workspace + fetch URL không hỏi.
  • --yes-tools tự đồng ý prompt nhưng không vượt blocklist/read-only; shell vẫn cần --allow-shell. Không có TTY thì prompt bị coi là từ chối.
  • --block-tool NAME (lặp lại được, hỗ trợ glob) + file ~/.config/daniwm/ai.tools.blocklist; tool bị chặn không xuất hiện trong request.
  • --deny-path GLOB chặn đọc/ghi và ẩn entry khỏi list/find/search (ưu tiên cao hơn write allowlist); --write-path GLOB giới hạn nơi được ghi; --allow-domain HOST ghim domain cho fetch_url (kiểm cả redirect).
  • Ghi/sửa file dùng file tạm + publish atomic, giữ quyền; file mới mode 600; giới hạn 64 KiB/file; từ chối path tuyệt đối, .., symlink, hardlink, file ẩn/nhạy cảm, device/FIFO.
  • /root <dir> đổi tool root ngay trong chat (xoá hội thoại để tránh lẫn project); /shell on|off bật/tắt shell cho phiên.
  • Budget mỗi lượt user: mặc định 64 tool call và 1 MiB tool-result (đổi bằng --max-tool-calls/--max-tool-output).

Custom tools

Mỗi tool = 1 manifest <ten>.json + script bất kỳ trong ~/.config/daniwm/ai.tools/ ($XDG_CONFIG_HOME được tôn trọng). Arguments validate theo JSON Schema con rồi gửi qua stdin (không qua shell); command là argv chạy trực tiếp với cwd = tool root; biến môi trường chứa *API_KEY*/*TOKEN*/*SECRET*/*PASSWORD*/*CREDENTIAL* không được truyền; confirm: true để hỏi trước khi chạy. Tên tool khớp ^[a-z][a-z0-9_]{1,40}$, tối đa 32 custom tool; manifest lỗi bị bỏ qua và ghi trong --show-config.

{
  "name": "btc_market",
  "description": "Read public Binance USD-M futures data. Read-only.",
  "command": ["python3", "{manifest_dir}/btc_market.py"],
  "timeout": 30,
  "output_limit": 131072,
  "confirm": false,
  "parameters": {"type": "object", "properties": {"symbol": {"type": "string"}}}
}
mkdir -p ~/.config/daniwm/ai.tools
cp ~/daniwm/ai.tools/* ~/.config/daniwm/ai.tools/
dani-ai "Lay du lieu BTC 4h va nhan xet xu huong"   # model tự gọi btc_market
dani-ai --tools-dir ./ai.tools tools                # xem tool từ thư mục khác
Gold = futures proxy: tool xauusd_market lấy dữ liệu Yahoo Finance GC=F (COMEX gold futures), không phải XAUUSD spot; giá có thể trễ, lệch basis và bị ảnh hưởng roll hợp đồng. Không đặt lệnh, không có funding/OI — không dùng làm execution feed. Yahoo có thể rate-limit hoặc block.
Không phải sandbox: --tool-root chỉ là working directory, không ngăn run_command hay custom tool truy cập ngoài thư mục. Shell chạy bằng quyền của bạn. Chặn run_command hoặc dùng --no-tools khi không tin nội dung đầu vào.

Trong dani-ai chat, lệnh bắt đầu bằng /.

Tab hoàn thành lệnh, ↑ gọi lại dòng đã nhập, Ctrl+D thoát khi dòng trống. Phiên tự lưu với ID riêng; last.json chỉ là checkpoint publish gần nhất nên khi nhiều phiên chạy song song, hãy dùng ID cụ thể với --continue. Ghi checkpoint và /save được serialize bằng flock trên .history.lock.

Ví dụ: dani-ai chat --deny-path 'private' --write-path 'src' --allow-domain docs.python.org — chặn đọc/ghi private, chỉ cho ghi trong src, chỉ fetch đúng host đã khai báo.
Private mode: --no-history không đọc/ghi readline history, không autosave, không checkpoint tool; /save, /resume, /export, /delete bị tắt. Đây không phải chế độ offline hay sandbox — provider vẫn nhận prompt, tool vẫn có thể ghi workspace.

Bảo mật

Key của bạn, dữ liệu của bạn — kiểm tra quyền truy cập trước khi bật tool.

  • Đặt chmod 600 ~/.config/daniwm/ai.key (và ai.profiles.json); không commit key hay file lịch sử vào Git.
  • Nội dung chat, ảnh, kết quả tool đều gửi tới provider API đang cấu hình — ưu tiên HTTPS cho endpoint remote; redirect khác origin (kể cả HTTPS → HTTP) bị chặn để không lộ key.
  • Session/history ghi atomic với thư mục 0700, file 0600, nhưng là plaintext, không mã hoá. --no-history cho phiên không lưu history/autosave.
  • Export giữ nguyên system prompt, tool output và attachment — không scrub secrets; không in nội dung export ra terminal, bạn tự chọn nơi lưu.
  • Nội dung file, trang web, output lệnh có thể chứa prompt injection — coi là dữ liệu, không phải chỉ dẫn.
  • run_command và custom tool không bị sandbox: có thể sửa/xoá file, truy cập mạng ngoài tool root. Không chạy bằng root; dùng --no-tools khi chỉ cần hỏi đáp.
  • EWMH client message của daniwm là trust-based theo spec (pager/wmctrl cần vậy) — không kiểm tra sender.
  • Chỉ cài custom tool đã đọc mã nguồn; tránh --yes-tools với tool chưa tin cậy.

Sự cố

Bắt đầu với dani-ai --show-config để kiểm tra endpoint, model, tool root và nguồn cấu hình.

make lỗi thiếu header

Cài đủ libX11-devel libXinerama-devel libXrandr-devel libXft-devel; dani-comp cần thêm Composite/Damage/Render/Fixes.

Không tìm thấy lệnh dani-ai / daniwm

Kiểm tra symlink, quyền thực thi và thêm ~/.local/bin vào PATH. Trong repo có thể chạy trực tiếp ./dani-ai --version.

Lỗi 401 / 403

Kiểm tra dòng đầu của ai.key, hạn dùng key và quyền truy cập model. Khi dùng --profile, key chỉ lấy từ biến môi trường khai báo trong profile — không fallback sang ai.key.

404 hoặc model không tồn tại

Base URL thường kết thúc bằng /v1 và không thêm /chat/completions. Chạy dani-ai models nếu provider hỗ trợ.

API không hỗ trợ tools / streaming

Thử dani-ai --no-tools --no-stream "Xin chào", hoặc khai báo capabilities đúng trong profile. Stream lỗi/cụt (thiếu [DONE]) được báo lỗi và không lưu thành câu trả lời hoàn chỉnh.

Session bị từ chối khi --continue

Session v2 lưu project root, API base và profile; resume khác project/provider/model sẽ bị chặn. Chỉ dùng --trust-session sau khi kiểm tra nội dung, và model vẫn phải khớp profile.

Timeout hoặc 429

Tăng --timeout, hoặc bật --http-retries 1..3 khi provider trả 429/502/503/504. Trong chat, gõ /retry nếu lượt đó chưa có tool call.

Không paste được ảnh

Kiểm tra xclip/wl-paste, clipboard đang chứa ảnh (≤10 MiB), terminal hỗ trợ bracketed paste và model có vision. Với profile vision:false, ảnh bị từ chối cả khi resume.

Tool không xuất hiện hoặc bị từ chối

Kiểm tra --no-tools, blocklist, --permissions read-only và thư mục manifest; manifest lỗi được ghi trong --show-config. Nếu không có TTY, prompt xác nhận bị coi là từ chối. Kiểm tra cả --deny-path/--write-path nếu file bị chặn.

/undo bị từ chối

Undo chỉ chạy khi file còn đúng trạng thái AI để lại và lượt đó không có shell/custom tool; nếu bạn đã sửa file sau đó, hãy khôi phục bằng Git/backup.
