## 3. Findings

### CRITICAL

No confirmed CRITICAL finding. Rationale: 100-window open/close storms, focused-window destroy, fullscreen destroy, transient-before-parent destroy, and synthetic-withdraw/re-map cycles all ran under an ASan+UBSan build with zero sanitizer reports and a consistent `_NET_CLIENT_LIST`. The event-loop paths that free memory (`unmanage`) clear all global references first (`detach`, `client.c:54-62`).

### HIGH

**H1 — Ghost clients: client-initiated unmap without synthetic event never unmanages.**
- Why dangerous: the `Client` stays in `clients`, stays in `_NET_CLIENT_LIST`, keeps its `_NET_WM_DESKTOP`, counts toward tiling/focus fallback, and its XID may later be recycled by the server to a *different* window (`find()` collision → wrong-window focus/geometry).
- Location: `src/main.c:417-419` (`if (c && e->send_event) unmanage(...)`).
- Reproduction (confirmed): map a window with python-xlib, `unmap()` it plainly, wait — `_NET_CLIENT_LIST` length stays 1. Destroying it afterwards recovers (list 0), so the leak is bounded by client lifetime, but long-lived hidden windows (e.g. apps that unmap-to-hide) accumulate.
- Recommended fix: track expected-unmap state or set/check ICCCM `WM_STATE`. Minimal robust fix: on non-synthetic `UnmapNotify` for a managed client, probe state; combined with setting `WM_STATE`=`WithdrawnState`/`NormalState` in `manage`/`unmanage`, unmanage when the client is truly withdrawn rather than WM-hidden.
- Confidence: confirmed bug (live test).

**H2 — No FocusIn/FocusOut handling, no `WM_TAKE_FOCUS`, no ICCCM input-hint check; unconditional `XSetInputFocus`.**
- Why dangerous: `focus_ex` (`src/client.c:111-129`) calls `XSetInputFocus` on every focus path — including windows with `WM_HINTS.input=False` and GloballyActive clients that expect `WM_TAKE_FOCUS` via ClientMessage. Those clients never receive focus per spec; meanwhile real focus changes done by clients arrive as `FocusIn`/`FocusOut` — which are selected (`client.c:459`) but dropped by `default:` (`main.c:682`) — so `sel`/`_NET_ACTIVE_WINDOW` silently desync from reality.
- Locations: `src/client.c:127`; `src/client.c:459` (mask selected, never consumed); missing atoms anywhere (`grep TakeFocus|FocusIn` → only the two `WM_HINTS` urgency reads).
- Reproduction: any NoInput window or TakeFocus client (some Java/Electron dialogs); or a client calling `XSetInputFocus` itself — `sel` points elsewhere afterwards.
- Recommended fix: handle `FocusIn` (update `sel`/urgency when a managed window takes focus itself); check `WM_HINTS.input` before `XSetInputFocus`; implement `WM_TAKE_FOCUS` ClientMessage for clients advertising it; keep the `RevertToPointerRoot` fallback for empty workspaces.
- Confidence: confirmed by inspection (code + atom grep).

**H3 — `xerror_ignore` swallows every X error for the rest of the process lifetime.**
- Why dangerous: `BadWindow` from a stale XID (destroyed window still referenced by `drag.nb_up/nb_dn/swap_target`, `last_kill_win`, `ff_seq[]`, task hitboxes) becomes invisible — bugs that would be loud during testing are silent in production. It also hides `BadValue`/`BadMatch` from geometry mistakes.
- Location: `src/main.c:121` + `XSetErrorHandler(xerror_ignore)` at `main.c:200`.
- Recommended fix: keep ignore as default but wrap risky sequences (`XSetInputFocus`, drag-snapshot `XGetWindowAttributes` loops, `tiled_at`) in a temporary trapped-error + `XSync` pattern that logs and continues; or at minimum log `request_code/minor_code` at debug level.
- Confidence: confirmed architectural risk (handler text is unconditional).

**H4 — MapRequest unconditionally focuses the mapping window.**
- Why dangerous: any background window that (re)maps — progress dialogs, splash screens, apps mapping helper windows — steals focus and, in monocle, yanks the visible window (`focus(c)` → `arrange()` shows `sel`). Breaks the focus-fight guard's intent for the map path (the guard only covers `_NET_ACTIVE_WINDOW` ClientMessages).
- Location: `src/main.c:398-404`.
- Recommended fix: focus on MapRequest only for the first map of a newly managed window (`manage()` already focuses); for an already-managed window remapping, just `arrange()` and let hover/pager decide, or route through `fight_check()`.
- Confidence: confirmed by inspection; likely bug (user-visible focus theft), not a crash.

### MEDIUM

**M1 — Direct `_NET_WM_STATE` property writes are ignored; WM and client disagree about fullscreen.**
- Confirmed by test: setting `_NET_WM_STATE=FULLSCREEN` via `change_property` left geometry tiled (`8,56 1260x732`, not `0,0 1280x800`); later `ewmh_update_state()` will overwrite the client's value. EWMH-correct clients use ClientMessage (handled), so this is a robustness gap, not a mainstream break. Location: `main.c:562-591` (no `A_NET_WM_STATE` arm). Recommended fix: on `PropertyNotify(_NET_WM_STATE)` for a managed client, reconcile `fullscreen`/`urgent` bits (or at least re-assert WM state).

**M2 — Urgency is set but never cleared from the property side.**
- `main.c:578-584` sets urgent on `XUrgencyHint`; nothing clears it when the client clears the hint (only focusing clears). Stale urgent highlighting on bar/workspace. Recommended fix: mirror the flag — `set_urgent(c, !!(wmh->flags & XUrgencyHint))` when `c != sel`, plus handle `_NET_WM_STATE_DEMANDS_ATTENTION` removal in M1's reconciler.

**M3 — `view()` unmaps the old workspace *after* arranging the new one.**
- `src/client.c:158-175`: `arrange()` (maps new ws) runs before old-ws `XUnmapWindow`s. Both sets are briefly mapped; every switch emits a burst of `UnmapNotify`s and double-touches the server. Same pattern in `send_to` (`client.c:177-196`). Recommended fix: unmap old first, then `arrange()`, then focus — matching `k_reload`'s order. Confirmed by inspection.

**M4 — ICCCM `WM_STATE` (`NormalState`/`WithdrawnState`/`IconicState`) is never set.**
- The WM never publishes `WM_STATE` on managed windows (no references anywhere — grep confirms). Session managers, pagers, and `xprop`/`xwininfo` state queries misreport; also removes the standard disambiguator for H1-class unmap races. Missing feature / likely bug. Recommended fix: set `NormalState` in `manage()`, `WithdrawnState` in `unmanage()`, `IconicState` for monocle-hidden/parked if desired.

**M5 — `kill_client` sends `WM_DELETE_WINDOW` with `data.l[1] = CurrentTime` and re-interns atoms per call.**
- `src/client.c:239-259`: ICCCM §4.1.8 expects a timestamp in `data.l[1]`; `CurrentTime` (0) is technically wrong (works against most clients because they ignore it). Also `XInternAtom("WM_DELETE_WINDOW"/"WM_PROTOCOLS")` on every kill instead of caching. Recommended fix: cache the atoms at startup; pass a real timestamp from the triggering event where available.

### LOW

- **L1** `ConfigureRequest` synthetic reply hardcodes `above=None` (`main.c:535`) — stacking info lost to the client. Harmless for tiling; note only.
- **L2** Floating geometry cache unclamped (`main.c:511-515`, `mouse.c:217-221`, `keys.c:186-194`): negative/huge/zero sizes stored; zero is later healed (`client.c:294`), `XResizeWindow` with 0 is a trappable error (masked by H3). Clamp to ≥1 and sane maxima.
- **L3** Stale-XID holders: `drag.nb_up/nb_dn/swap_target` (`mouse.c`), `last_kill_win` (`client.c:261`), `ff_seq[]` (`main.c:44`), `task_hit_win[]`. All are validated with `find()` before use (good), but server XID recycling could theoretically alias a *new* window. Negligible in practice; document, or store a generation check.
- **L4** `k_reload` maps every current-ws window before `arrange()` re-hides monocle-hidden ones (`config.c:766-769`) — transient over-map, no `XFlush` between, so likely invisible; still, skip `c->hidden` in the loop.
- **L5** `_NET_SUPPORTED` omits `_NET_WM_WINDOW_TYPE` (yet types are honored in `ewmh_isfloating_type`), `_NET_WM_NAME`, `_NET_MOVERESIZE_WINDOW`, `_NET_RESTACK_WINDOW`, `_NET_DESKTOP_VIEWPORT`. Advertise what is honored.
- **L6** No `WM_NORMAL_HINTS` (min/max size, aspect, resize increments) — tiled resizes can produce sizes the client considers illegal; clients cope (they must), but size-hint-aware tiling would be more correct. Missing feature, out of scope for minimal WM.
- **L7** Scratchpad park (`keys.c:33-66`) leaves `ws_sel[curws]` pointing at the parked client when no other window exists (healed on next `view` by the `ws_sel[n]->ws == n` check in `client.c:164` — verified safe, but fragile).
- **L8** `finalize_nws` sentinel migration (`config.c:744-747`) is correct for grow/shrink but depends on the parked window being exactly at the old sentinel; two parked windows (only possible via restart-adopt edge) would fold one into `NWS-1`. Theoretical; single scratchpad enforced by `findscratch`.
- **L9** Tray `XSelectInput(..., ResizeRedirectMask)` on icons (`tray.c:217`) overwrites the icon's mask and steals resize-redirect — fine for icons, surprising for anything else; the 64px size guard (`tray.c:196-200`) is the load-bearing protection. Keep the guard.
- **L10** `_NET_CLIENT_LIST` excludes the parked scratchpad (`ewmh.c:133-145` filters `ws>=NWS`). Defensible (hides parked window from pagers) but strict EWMH expects all managed toplevels listed; sticky `0xFFFFFFFF` desktop + list membership is the standard combo.

### What is correct (with reasons)

- `DestroyNotify` → `unmanage` unconditionally: safe no-op on unknown windows; all pointer clears happen in `detach` *before* `free`, so no UAF; verified under ASan with 100-window storms.
- Synthetic-withdraw path (`send_event` check): correct per ICCCM for well-behaved clients; withdraw→`unmanage`→re-map→`manage` cycle tested working.
- Transient dialogs: hint read once, never stored — parent-destroy test left the dialog managed with no dangling reference. Correct.
- Tiled `ConfigureRequest` denial + synthetic `ConfigureNotify`: spec-compliant reply present (`main.c:522-538`).
- `detach()` clears `sel` and every `ws_sel[i]` before free; `view()` revalidates `ws_sel[n]` via `find()+ws` check — no dangling focus memory. `zoom()`'s mid-op re-append guard (`client.c:332-336`) keeps the list valid.
- `raise_floats` preserves server stacking order instead of list order (`layout.c:14-33`) — avoids undoing explicit raises; correct and subtle.
- OOM guards: `calloc` results checked in `manage`, `manage_dock`, `tray_add`, `ewmh_client_list`, `tray_layout_icons`. Property buffers always `XFree`d on all paths checked.
- 32-bit property unpacking via `(unsigned long *)/(long *)` (`ewmh.c`, `main.c:is_sticky`): correct in practice — Xlib expands 32-bit server data into `long` array elements; comparisons against `0xFFFFFFFF`/`NWS` behave as intended on 64-bit LE.
- `EnterNotify` filtering (grab modes, `NotifyInferior`, hover-lock) and the no-raise hover path: correct; nested floating windows stay reachable.
- `MappingNotify` re-grab: correct against keymap-change bind loss.
- Focus-fight duel detector: correctly scoped to ClientMessage demands; keys/buttons bypass by calling `focus()` directly.

## 4. Summaries

**Top 10 by severity:** H1 ghost-on-unmap · H2 focus-model gaps (TakeFocus/input-hint/FocusIn) · H3 error-swallowing handler · H4 MapRequest focus-steal · M1 direct-state-write ignored · M2 urgency never cleared · M3 view() map-before-unmap · M4 WM_STATE never published · M5 WM_DELETE timestamp/atom caching · L2 unclamped floating geometry.

**X11 protocol compliance:** SubstructureRedirect ownership correct (second-WM detection via error trap). Map/Configure/Destroy handling is sound for mainstream clients; withdraw handling is ICCCM-correct only for synthetic events (H1). EWMH coverage is good for a minimal WM (supporting window + PID, client list, active window, desktops/names, fullscreen, demands-attention, struts/workarea, dock + tray selection) with advertisement gaps (L5) and no moveresize/restack/maximize (by design). ICCCM gaps: no `WM_STATE` (M4), no `WM_TAKE_FOCUS`/input-hint (H2), no size hints (L6), `WM_DELETE` timestamp nit (M5).

**Client lifecycle/state machine:** managed→mapped/unmapped/destroyed, focus transitions, tile↔float↔fullscreen, ws/mon moves all preserve list/pointer invariants (`detach`+`find` discipline, no stored transient pointers). Verified transitions: 100× open/close, focused destroy (focus falls back to root + `_NET_ACTIVE_WINDOW` cleared), fullscreen destroy, transient↔parent destroy orderings, synthetic withdraw/re-map. One leak: plain-unmap → stale managed entry (H1). One ordering wart: `view`/`send_to` map-before-unmap (M3).

**Memory safety:** ASan+UBSan over the full adversarial suite: zero reports. Ownership boundaries are clean (free only in the three `un*` functions, always after unlink+clear). No double-free paths (unknown-window unmanage is a no-op; `tray_remove`/dock paths unlink-then-free once). Residual risks are XID-reuse aliasing (L3), not pointer lifetime. Compiler posture is good: project flags (`-Wall -Wextra -Wpedantic -Wshadow -FORTIFY -fPIE`) build warning-free; extra `-Wconversion -Wsign-conversion -fanalyzer` surfaced only one sign nit (`bar.c:774`) and one analyzer note in config argv handling.

**Robustness:** Survives open/close storms and property storms (100× `WM_NAME` changes) without desync or crash; restart-in-place preserves workspace/fullscreen/focus via root properties; RandR replug re-tiles idempotently; select-loop has error cap and rename-pipe integration. Weak spots: H3 masks future faults; H1 accumulates ghosts for hide-instead-of-withdraw clients; H2/H4 lose or steal focus on non-mainstream clients.

## 6. Recommended fix order

1. H1 (ghost unmap) + M4 (`WM_STATE` publish) together — same mechanism.
2. H2 (FocusIn handling + input-hint check + `WM_TAKE_FOCUS`) — biggest compat win after H1.
3. H4 (MapRequest no-steal) — small, high-visibility.
4. H3 (trapped-error logging wrapper) — enables confident fixing of everything else.
5. M1 + M2 (state/urgency reconciliation on `PropertyNotify`).
6. M3 (unmap-before-arrange in `view`/`send_to`), M5 (atom cache + timestamp), then LOWs opportunistically (L2 clamp, L4 reload loop, L5 `_NET_SUPPORTED` advertisement).

Compiler/sanitizer recommendations: keep current flags; add `-Wconversion -Wsign-conversion` to CI (one existing nit), run the Xvfb python-xlib suite above under `-fsanitize=address,undefined` (already proven clean), and add LeakSanitizer (included in ASan by default) to a restart-in-place cycle test.
